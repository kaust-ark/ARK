التوثيق

التثبيت والتهيئة ومرجع المطوّرين للاستضافة الذاتية لـ Idea2Paper. اسم المنتج هو Idea2Paper؛ وخلف الكواليس يعمل إطار ARK، لذا تستخدم أوامر سطر الأوامر والمسارات أدناه الاسم ark.

التثبيت

تثبيت ذاتي بنقرة واحدة (Linux / macOS):

curl -fsSL https://idea2paper.org/install.sh | bash

يقوم السكربت بما يلي:

  1. يثبّت miniforge (إن لم يكن موجوداً)، ويبني بيئتَي conda باسم ark-base وark، ويثبّت ARK عبر pip بوضع editable في ~/ARK، ويضيف واجهتَي سطر الأوامر Claude Code وGemini.
  2. يطلب مفتاح Gemini API، ورمز Claude OAuth (sk-ant-oat01-…)، والبريد الإلكتروني لتسجيل الدخول إلى لوحة التحكم. اضغط Enter لتخطي أيٍّ منها.
  3. يثبّت لوحة التحكم كخدمة systemd --user على المنفذ 9527.
  4. يطبع رابطاً سحرياً لمرة واحدة لبريدك الإلكتروني. انقر عليه مرة واحدة → تصبح مسجَّل الدخول إلى لوحة التحكم المحلية. بدون SMTP وبدون Google OAuth.

خيارات مفيدة:

  • --no-webapp — تخطّي خدمة لوحة التحكم المحلية
  • --prefix DIR — تثبيت مصدر ARK في مجلد مخصّص
  • --branch NAME / --repo URL — تجاوز مصدر git
  • --no-research / --no-base — تخطّي المكوّنات الاختيارية
  • --noninteractive — تخطّي الأسئلة التفاعلية (CI / تشغيل غير مُراقَب)
  • --dry-run — طباعة الخطة دون إجراء أي تغييرات

يمكنك أيضاً تعبئة الإجابات مسبقاً عبر متغيرات البيئة: ARK_GEMINI_KEY وARK_CLAUDE_OAUTH وARK_LOGIN_EMAIL. شغّل ark doctor للتحقق، وark webapp login <email> في أي وقت للحصول على رابط تسجيل دخول جديد. السكربت الكامل: install.sh.

التثبيت اليدوي — إن كنت تفضّل القيام بذلك بنفسك:

conda env create -f environment.yml      # creates ark-base (Linux)
conda create -n ark python=3.11 -y
conda activate ark
pip install -e ".[research,webapp]"
ark doctor

المتطلبات المسبقة

  • Python 3.9+
  • خلفية AI واحدة على الأقل — مثبَّتة ومُوثَّقة:
    • Claude Code CLI (claude) — مُوصى به
    • Gemini CLI (gemini)
    • Codex CLI (codex)
  • حزمة أدوات LaTeX (اختيارية) — pdflatex وbibtex لتجميع ملفات PDF
  • PyYAML — يُثبَّت تلقائياً مع Idea2Paper
💡 نصيحة: يُوصى باستخدام Claude Code مع اشتراك Max. وكلاء Idea2Paper مستهلكون جداً للرموز (tokens) — قد يستهلك تشغيل ورقة واحدة أكثر من 50 ألف سطر من مخرجات الوكلاء عبر جميع التكرارات.

البدء السريع

أنشئ مشروعاً جديداً، وأدخل عنوان ورقتك وفكرتك، ثم دع Idea2Paper يتولى الباقي:

# Create a new project (interactive wizard)
ark new my-project

# Run the full pipeline
ark run my-project

# Check progress anytime
ark status my-project

سيسألك معالج ark new عن:

  1. عنوان الورقة — مثال: "Efficient Cache-Aware Matrix Multiplication on Modern CPUs"
  2. الفكرة البحثية — فقرة تصف المساهمة الأساسية والمنهجية
  3. المؤتمر المستهدف — NeurIPS أو ICML أو ICLR أو ACL أو IEEE وغيرها
  4. مجلد الكود — مكان وجود كود التجارب
  5. خلفية النموذج — Claude أو Gemini أو Codex

يمكنك أيضاً البدء انطلاقاً من ملف PDF لمقترح موجود:

ark new my-project --from-pdf proposal.pdf

ark new

إنشاء مشروع بحثي جديد عبر معالج تفاعلي.

ark new <project-name> [options]
الخيارالوصف
--from-pdf <path>بدء المشروع من ملف PDF لمقترح
--venue <venue>تحديد المؤتمر المستهدف (مثل neurips أو icml)
--model <model>خلفية AI: claude أو gemini أو codex

ينشئ هذا الأمر ARK/projects/<project-name>/ ويحتوي على:

  • config.yaml — إعدادات المشروع
  • hooks.py — منطق مخصّص للبحث/توليد الأشكال
  • agents/ — ملفات الموجّهات لكل دور من أدوار الوكلاء

ark run

بدء خط أنابيب البحث الذاتي لمشروع ما.

ark run <project-name> [options]
الخيارالوصف
--mode paper|researchوضع خط الأنابيب (الافتراضي: paper)
--max-iterations <n>الحد الأقصى لتكرارات المراجعة (الافتراضي: 14)
--max-days <n>الحد الأقصى للأيام في وضع البحث
📝 ملاحظة: في وضع paper، يشغّل Idea2Paper خط الأنابيب الكامل ذا المراحل الثلاث (بحث → تطوير → مراجعة). أما في وضع research، فيركّز على تصميم التجارب وتنفيذها دون كتابة الورقة.

يمكنك أيضاً استدعاء المنسّق مباشرة لمزيد من التحكم:

# Paper mode with specific model and iteration limit
python -m ark.orchestrator --project my-project --mode paper --model claude --max-iterations 20

# Research mode with day limit
python -m ark.orchestrator --project my-project --mode research --model claude --max-days 3

# Background execution with logging
nohup python -m ark.orchestrator --project my-project --mode paper --model claude \
  > auto_research/logs/orchestrator.log 2>&1 &

ark status

التحقق من التقدم الحالي لمشروع ما.

ark status <project-name>

يعرض: التكرار الحالي، ودرجة المراجِع، والمرحلة، وتفصيل التكلفة، وأحدث إجراءات الوكلاء.

ark monitor

مراقبة خط الأنابيب في الوقت الفعلي — بث مباشر لمخرجات الوكلاء وتغيّرات الحالة.

ark monitor <project-name>

ark update

إرسال تعليمات إلى خط الأنابيب أثناء التشغيل. مفيد لتوجيه الوكلاء دون إيقافهم.

ark update <project-name>

# Example instructions:
# "Focus on the related work section"
# "Add a comparison with TransformerFAM"
# "Increase the font size in Figure 3"

ark stop

إيقاف خط أنابيب قيد التشغيل بسلاسة. تُحفَظ الحالة في نقطة تفتيش حتى تتمكن من الاستئناف لاحقاً.

ark stop <project-name>

ark delete

حذف مشروع وجميع إعداداته.

ark delete <project-name>
⚠️ تحذير: يحذف هذا الأمر إعدادات المشروع الموجودة تحت ARK/projects/. لن يتأثر مجلد الكود الخاص بك ولا الأوراق المولَّدة.

إعدادات المشروع

لكل مشروع ملف config.yaml يتحكم في جميع جوانب خط الأنابيب:

# ARK/projects/my-project/config.yaml
code_dir: /home/user/my-research        # Where experiment code lives
venue: NeurIPS                           # Target venue
venue_format: neurips                    # LaTeX template format
venue_pages: 9                           # Main content page limit

title: "My Paper Title"
model: claude                            # AI backend (claude/gemini/codex)

# Directory structure
latex_dir: paper                         # LaTeX source directory (relative to code_dir)
figures_dir: paper/figures               # Generated figures
scripts_dir: code                        # Experiment scripts

# Figure generation
create_figures_script: code/create_paper_figures.py

# Quality threshold — stop when reviewer score hits this
paper_accept_threshold: 8

# Goal Anchor — keeps agents focused across iterations
goal_anchor: |
  ## Goal Anchor
  **Paper Title**: My Paper Title
  **Target Venue**: NeurIPS 2025
  **Core Contributions**:
  1. First contribution...
  2. Second contribution...

# Compute settings (optional)
use_slurm: false
slurm_job_prefix: EXP_
conda_env: my-env

# Telegram notifications (optional)
telegram_bot_token: "YOUR_BOT_TOKEN"
telegram_chat_id: "YOUR_CHAT_ID"

الخطافات المخصّصة

يمكن لكل مشروع تعريف ملف hooks.py لمنطق مخصّص. يتيح لك هذا حقن سلوك خاص بالمشروع في خط الأنابيب:

# ARK/projects/my-project/hooks.py

def pre_experiment(config, state):
    """Called before each experiment run."""
    pass

def post_experiment(config, state, results):
    """Called after experiment completes. Process results here."""
    pass

def create_figures(config, state):
    """Custom figure generation logic."""
    pass

المرحلة 1: البحث

تستخدم مرحلة البحث «بحث عميق» (Deep Research) لجمع المعرفة الخلفية:

  1. تأخذ عنوان ورقتك وفكرتك كمدخلات
  2. تجري مسحاً شاملاً للأدبيات
  3. تحدد الأعمال ذات الصلة والفجوات وتموضع الورقة
  4. تُخرج ملخصاً بحثياً منظماً إلى auto_research/state/
💡 نصيحة: ثبّت بـ pip install -e ".[research]" لتفعيل تكامل «بحث عميق». بدونه، يمكنك تخطي هذه المرحلة وتقديم مسح الأدبيات بنفسك.

المرحلة 2: التطوير

تتولى مرحلة التطوير تصميم التجارب وتنفيذها:

  1. المخطِّط ينشئ خطة تجارب بناءً على الملخص البحثي
  2. المجرِّب يكتب سكربتات التجارب ويرسلها (يدعم Slurm والتشغيل المحلي والسحابة)
  3. الباحث يحلل النتائج ويحدد فجوات الاكتمال
  4. الكاتب ينتج المسودة الأولى للورقة بصيغة LaTeX

المرحلة 3: المراجعة

مرحلة المراجعة هي حيث يحدث السحر. في كل تكرار:

  1. التجميع — LaTeX → PDF، وتوليد صور الصفحات للمراجعة البصرية
  2. المراجعة — وكيل المراجِع يقيّم الورقة (1–10) ويكتب ملاحظات تفصيلية
  3. التخطيط والتنفيذ — المخطِّط يحوّل الملاحظات إلى مهام؛ ينفّذها الكاتب/المجرِّب/الباحث
  4. الإخراج البصري — إصلاح الأشكال، وإعادة التجميع، والتحقق من التغييرات

تستمر العملية حتى:

  • تبلغ درجة المراجِع قيمة paper_accept_threshold (الافتراضي: 8)
  • يُبلَغ الحد الأقصى لعدد التكرارات
  • توقفها يدوياً بأمر ark stop

عند بلوغ عتبة الدرجة، يشغّل Idea2Paper تكرار تنظيف أخيراً لمعالجة أي مشكلات طفيفة متبقية قبل إنتاج ملف PDF النهائي.

نظام الذاكرة

يتتبع Idea2Paper التقدم عبر التكرارات لمنع الحلقات المفرغة واكتشاف الركود:

# Stored in auto_research/state/memory.yaml
scores: [5.0, 5.5, 6.0, 6.2, 6.5, 7.0, 7.2]
best_score: 7.2
stagnation_count: 0

تتبع الدرجات

يحتفظ بسجل درجات المراجِع (آخر 20 تكراراً). يُستخدم لقياس التقدم وإطلاق التدخلات.

اكتشاف الركود

إذا لم تتحسن الدرجة لعدة تكرارات متتالية، يقوم Idea2Paper بما يلي:

  1. يُنبّه المخطِّط إلى حالة الركود
  2. يستدعي وكيل المصحِّح الفوقي لتشخيص على مستوى النظام
  3. يرسل إشعار Telegram (إن كان مهيّأً) يطلب تدخلاً بشرياً

تتبع تكرار المشكلات

يحصي عدد المرات التي تعاود فيها كل مشكلة الظهور عبر المراجعات. إذا استمر فشل إصلاح ما، يحظر Idea2Paper الاستراتيجية غير الفعالة ويجرّب مقاربات بديلة.

مرساة الهدف

يتضمن كل استدعاء وكيل «مرساة الهدف» (Goal Anchor) — وصفاً ثابتاً للأهداف الأساسية للمشروع. يمنع هذا الوكلاء من الانحراف عن الموضوع عبر التكرارات الكثيرة.

تكامل Telegram

يستطيع Idea2Paper إرسال إشعارات فورية واستقبال تعليمات أثناء التشغيل عبر Telegram:

الإعداد

# Interactive setup
ark setup-bot

# Or manually add to config.yaml:
telegram_bot_token: "YOUR_BOT_TOKEN"
telegram_chat_id: "YOUR_CHAT_ID"

الميزات

  • إشعارات التكرارات — تحديثات الدرجة بعد كل دورة مراجعة
  • توصيل PDF — اطلب ملف PDF الحالي للورقة في أي وقت
  • تعليمات أثناء التشغيل — أرسل نصاً لتوجيه الوكلاء
  • تنبيهات الركود — إشعار تلقائي عند تعثّر التقدم
  • تأكيدات استباقية — يسأل الوكلاء قبل إجراء تغييرات محفوفة بالمخاطر

Slurm / الحوسبة عالية الأداء

يدعم Idea2Paper تشغيل التجارب على عناقيد الحوسبة عالية الأداء المُدارة بواسطة Slurm:

# config.yaml
use_slurm: true
slurm_job_prefix: EXP_       # Prefix for job names
conda_env: my-env             # Conda environment to activate

عند تفعيل use_slurm: true، يقوم وكيل المجرِّب بما يلي:

  1. يولّد سكربتات دفعات Slurm بطلبات موارد مناسبة
  2. يرسل المهام عبر sbatch
  3. يراقب حالة المهام بواسطة squeue
  4. يجمع النتائج عند اكتمال المهام

في البيئات التي لا تستخدم Slurm، تعمل التجارب محلياً أو على أي خادم يمكن الوصول إليه عبر SSH.

إدارة الحالة

تُخزَّن جميع حالات التشغيل تحت <code_dir>/auto_research/:

auto_research/
├── state/
│   ├── paper_state.yaml      # Current paper metadata
│   ├── action_plan.yaml      # Current action plan from planner
│   ├── latest_review.md      # Most recent review output
│   ├── memory.yaml           # Score history, stagnation tracking
│   ├── checkpoint.yaml       # Resume checkpoint
│   └── findings.yaml         # Accumulated research findings
└── logs/
    └── *.log                  # Per-iteration agent logs

نقاط التفتيش والاستئناف

ينشئ Idea2Paper نقطة تفتيش تلقائياً بعد كل تكرار. إذا انقطع التشغيل، شغّل ark run مرة أخرى فحسب — سيستأنف من آخر نقطة تفتيش.

بداية جديدة

لإعادة البدء من الصفر، امسح ملفات الحالة:

rm -f auto_research/state/checkpoint.yaml \
      auto_research/state/paper_state.yaml \
      auto_research/state/action_plan.yaml \
      auto_research/state/latest_review.md \
      auto_research/state/memory.yaml

استكشاف الأخطاء

فشل تجميع LaTeX

تأكد من تثبيت pdflatex وbibtex. على Ubuntu:

sudo apt install texlive-full

انتهاء مهلة الوكيل أو فشله

راجع سجلات الوكلاء تحت auto_research/logs/. الأسباب الشائعة:

  • Claude Code CLI غير مُوثَّق — شغّل claude وأكمل تسجيل الدخول
  • تقييد المعدل (Rate limiting) — يملك Idea2Paper آلية إعادة محاولة مدمجة مع تأخير تصاعدي
  • سياق غير كافٍ — جرّب تبسيط مرساة الهدف

درجة عالقة / ركود

إذا استقرت درجة المراجِع دون تحسن:

  1. راجع auto_research/state/latest_review.md لمعرفة المشكلات المحددة
  2. أرسل تعليمات موجّهة عبر ark update أو Telegram
  3. فكّر في تعديل موجّهات الوكلاء في projects/<name>/agents/

خط الأنابيب لا يبدأ

  • تحقق من أن مسارات config.yaml مطلقة وموجودة
  • تأكد من تثبيت واجهة سطر الأوامر للنموذج المحدد: which claude
  • شغّل ark status <project> للحصول على مخرجات تشخيصية
تحتاج مساعدة؟ افتح مشكلة (issue) على GitHub أو راجع README لأحدث التحديثات.

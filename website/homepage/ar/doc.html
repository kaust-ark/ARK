يقوم نظام idea2paper بتنسيق عمل 6 وكلاء ذكاء اصطناعي متخصصين لتحويل فكرة بحثية إلى ورقة علمية كاملة — من تحليل المقترح، والبحث في المراجع، وتجارب Slurm، وصولاً إلى صياغة LaTeX والمراجعة العلمية المتكررة — كل ذلك مع بقائك في موقع التحكم عبر واجهة الأوامر (CLI)، أو لوحة التحكم، أو تيليجرام.

أعطه فكرة ومؤتمراً علمياً. وسيتولى idea2paper الباقي.

أسرع طريقة لتجربته هي النسخة المستضافة على idea2paper.org — سجّل الدخول ببريدك الإلكتروني، وأضف مفتاح OpenRouter واحداً، ثم انطلق. ورقة كاملة بنموذج اقتصادي مثل DeepSeek تُحاسَب عادةً بـ 10–25 دولاراً من رصيد API الخاص بك بحسب الطول — وتعرض لوحة التحكم التكلفة الفعلية لكل تشغيل. أما الاستضافة الذاتية فتثبيتها بسطر واحد (أدناه).

أوراق بحثية كتبها idea2paper


Budget-Constrained Multi-Modal Research Synthesis via Iterative-Deepening Agentic Search
القالب: EuroMLSys
HeteroServe: Capability-Weighted Batch Scheduling for Heterogeneous GPU Clusters in LLM Inference
القالب: ICML
TierKV: Prefetch-Aware Memory Tiering for KV Cache in LLM Serving
القالب: NeurIPS

بداية سريعة

curl -fsSL https://idea2paper.org/install.sh | bash

السكربت سيقوم بـ:

  1. كشف النظام، تثبيت miniforge عند الحاجة، إنشاء بيئتي ark-base و ark، تثبيت idea2paper بصيغة pip install -e داخل ~/ARK، وتثبيت OpenHands CLI (بيئة تشغيل الوكلاء، عبر uv — وهي تأتي مع نسخة Python 3.12 خاصة بها).
  2. سؤالك عن مفاتيح API وبريد إلكتروني لتسجيل الدخول إلى لوحة التحكم. الإعداد الموصى به هو مفتاح OpenRouter واحد — فهو يفتح كل النماذج إضافةً إلى البحث العميق وتوليد الأشكال؛ كما تعمل المفاتيح المباشرة من Anthropic / OpenAI / Gemini / DeepSeek أيضاً. اضغط Enter لتخطّي أي حقل.
  3. تثبيت لوحة التحكم كخدمة systemd --user على المنفذ 9527 (استخدم --no-webapp للتخطّي).
  4. طباعة رابط سحري لمرة واحدة للبريد المُدخل — انقر عليه مرة واحدة وستدخل لوحة التحكم المحلية. لا حاجة لـ SMTP أو Google OAuth.

بعد ذلك، لوحة التحكم على http://localhost:9527 هي واجهة العمل الرئيسية — إنشاء المشاريع، اختيار النموذج، التشغيل، والمراقبة. سطر الأوامر يعمل كذلك:

ark doctor          # التحقّق من التثبيت
ark new myproject   # معالج إنشاء المشروع
ark run  myproject
ark monitor myproject

شغّل ark webapp login <email> في أي وقت للحصول على رابط دخول جديد. خيارات السكربت الكاملة: website/homepage/install.sh --help.

البدء من ملف PDF موجود

ark new myproject --from-pdf proposal.pdf

يقوم idea2paper بتحليل ملف PDF باستخدام PyMuPDF + Claude Haiku، ويملأ البيانات تلقائياً، ويبدأ من المواصفات المستخرجة.

المتطلبات

  • Python 3.10+ مع pyyaml و PyMuPDF
  • بيئة تشغيل الوكلاء: OpenHands CLI (تُثبَّت عبر uv وتأتي مع Python 3.12 خاص بها) — بيئة تشغيل واحدة تدير Claude / GPT / Gemini / أي نموذج يدعمه LiteLLM، ويُختار النموذج لكل مشروع عبر model في config.yaml. ويمكن بدلاً من ذلك استخدام DeepSeek Harness كبيئة تشغيل بديلة تعزل الوكلاء في صندوق رمل مفروض على مستوى نظام التشغيل (model: dsh/deepseek-v4 — انظر docs/DEEPSEEK_HARNESS.md).
  • مفتاح API: مفتاح OpenRouter واحد يغطي كل النماذج، والبحث العميق (Perplexity)، والأشكال المولَّدة بالذكاء الاصطناعي؛ وتعمل مفاتيح المزوّد الواحد (Anthropic / OpenAI / Gemini / DeepSeek / …) أيضاً لكنها تفقد ما لا يقدّمه ذلك المزوّد.
  • اختياري: LaTeX (pdflatex + bibtex)، Slurm.

التثبيت

أسرع طريقة هي السكربت ذو الأمر الواحد المذكور في بداية سريعة، فهو يقوم بهذه الخطوات نيابة عنك ويطبع إرشادات البدء. للتنفيذ اليدوي:

# 1. أنشئ قالب بيئة المشاريع (المكدّس البحثي فقط، بدون كود idea2paper —
#    كل مشروع جديد يستنسخ هذه البيئة، لذلك يجب أن تبقى نظيفة).
conda env create -f environment.yml         # لأنظمة Linux (ينشئ "ark-base")
# أو لنظام macOS:
conda env create -f environment-macos.yml   # لأنظمة macOS (ينشئ "ark-base")

# 2. ثبّت idea2paper نفسه في بيئة منفصلة (ليست ark-base).
conda create -n ark python=3.11 -y
conda activate ark
pip install -e .                    # النواة الأساسية
pip install -e ".[research]"       # + Gemini Deep Research و Nano Banana
pip install -e ".[webapp]"         # + دعم لوحة التحكم وخدمة systemd

# 3. ثبّت OpenHands CLI (بيئة تشغيل الوكلاء). وهي أداة `uv` مستقلة
#    تأتي مع Python 3.12 خاص بها — وليست اعتمادية pip — ويجب أن تكون
#    على PATH كي تعثر عليها عملية المنسق الفرعية.
pip install uv && uv tool install --python 3.12 openhands

# 4. تحقّق (يفحص وجود openhands على PATH، وتوفر المفاتيح، وغير ذلك)
ark doctor

إطار العمل

ينسق idea2paper ثلاث مراحل — التهيئة والبحث، التطوير المتكرر، و المراجعة المتكررة — من خلال ذاكرة مشتركة، وGoal Anchor ثابت يُحقن من جديد في كل استدعاء وكيل لمنع الانحراف عبر التكرارات، إضافةً إلى تدخل بشري عبر لوحة التحكم أو تيليجرام.

مسار العمل

ينفذ idea2paper ثلاث مراحل بالتتابع. وتتكرر مرحلة المراجعة حتى تصل الورقة إلى الدرجة المستهدفة.

المرحلة ماذا يحدث
البحث مسار من 5 خطوات: الإعداد (بيئة conda) ← تحليل المقترح (researcher) ← بحث عميق (Perplexity عبر OpenRouter، أو Gemini) ← التخصيص (researcher) ← التمهيد (المهارات والاستشهادات)
التطوير دورة تجارب متكررة: تخطيط التجارب ← تشغيل التجارب (Slurm أو محلياً) ← تحليل النتائج ← تقييم الاكتمال
المراجعة تجميع ← مراجعة ← تخطيط ← تنفيذ ← تحقق، مع التكرار حتى تصل الدرجة ≥ العتبة المطلوبة

حلقة المراجعة

كل تكرار لمرحلة المراجعة يتكون من 5 خطوات:

الخطوة الوصف
التجميع تحويل LaTeX إلى PDF، حساب عدد الصفحات، وصور الصفحات
المراجعة مراجع ذكاء اصطناعي يعطي درجة من 1-10، ويسرد القضايا الكبرى والصغرى

التحقق التأكد من نجاح تجميع التعديلات؛ وإعادة إنشاء ملف PDF

تتكرر الحلقة حتى تصل الدرجة إلى عتبة القبول — أو تتدخل أنت عبر تيليجرام.

الضوابط وسجل الخطوات

التشغيل المستقل مراقَب ومضبوط ببوابات، وليس صندوقاً أسود.

  • سجل خطوات حي. كل ما يفعله أي وكيل — كل أمر bash، وكل تعديل ملف، ونتيجته — يتدفق إلى السجل لحظة حدوثه (لا مزيد من فراغ الثلاثين دقيقة)، وإلى ملف منظَّم agent_steps.jsonl. تُحجب القيم السرية تلقائياً. اضبط مستوى التفصيل عبر log_verbosity: quiet|normal|verbose|debug.
  • توقّف واسأل قبل الخطوات الخطرة. قبل حذف الملفات، أو إطلاق دفعة كبيرة من المهام، أو تجهيز مثيل سحابي مدفوع، أو التعامل مع بيانات الاعتماد، أو دفع البيانات وتسريبها للخارج، أو تجاوز سقف الإنفاق، يسألك idea2paper عبر تيليجرام وينتظر موافقتك (موافقة / رفض / تذكّر هذا القرار). وهو يتذكّر إجابتك فلا يعيد السؤال، ويرفض عند انتهاء المهلة، ويسمح تلقائياً مع التسجيل إن لم يكن تيليجرام مضبوطاً — فلا يتعطل شيء أبداً.
  • بوابة فحص الأفكار (Gate A / Gate B). تمر كل فكرة مُقدَّمة بمراجعة أخلاقية وعلمية قبل الإطلاق (Gate A)؛ وبعد مسح المراجع يجري فحص للجِدّة والنطاق (Gate B) يكشف التداخل مع الأعمال السابقة ويُدرج تحديداً صادقاً للنطاق في الورقة بدلاً من المبالغة في الادعاءات.
  • فحوص التسليم. قبل تسليم أي ورقة يجري التحقق منها وفق عقد صريح — وجود إفصاح استخدام الذكاء الاصطناعي، وحلّ جميع الاستشهادات، وقائمة مراجع غير فارغة، واستخدام الأشكال المولَّدة فعلاً، واحترام حد الصفحات. ويمكن تشغيل الفحوص نفسها بشكل مستقل عبر ark audit <project> [--repair].
  • إفصاح استخدام الذكاء الاصطناعي. تحمل كل ورقة تنويهاً بأنها أُنتجت بواسطة Idea2Paper وروجعت من قبل المؤلفين — يُدرج تلقائياً، ولكل مؤتمر.
  • طبقتا إنفاذ. تعترض أغلفة Shadow-PATH الأوامر الخطرة قبل تشغيلها؛ ويتكفل قاطع الدارة بأي شيء يتجاوزها. كما تخضع إجراءات المنسق الذاتية (تجهيز السحابة / git push / الإنفاق) للرقابة أيضاً — أما الأوامر التي تطلقها أنت بنفسك (ark clear، الحذف، الإيقاف) فلا.

يُضبط كل ذلك ضمن كتلة intervention: في config.example.yaml؛ ومستوى الاستقلالية الافتراضي (standard) لا يقاطعك إلا في الإجراءات عالية الخطورة فعلاً.

ما الذي يميز idea2paper

أدوات أخرى idea2paper
التحكم استقلالية كاملة — انحراف عن القصد، لا تصحيح أثناء التشغيل تدخل بشري: توقف عند القرارات الرئيسية، توجيه عبر تيليجرام أو الويب
التنسيق تخطيطات مكسورة، أخطاء LaTeX، تنظيف يدوي قوالب المؤتمرات + تحكم دون مستوى الصفحة للالتزام بالحد الأقصى للصفحات بدقة
الاستشهاد النماذج اللغوية تبتكر مراجع وهمية BibTeX من واجهات برمجية أولاً (DBLP / CrossRef / arXiv) مع مواءمة المحتوى مع الادعاء
المراجعة مراجعة نصية فقط لمصدر LaTeX مراجعة بصرية: صور الصفحات و المصدر، بتقييم وفق معايير المؤتمر
الأشكال أنماط افتراضية، أحجام خاطئة، لا وعي بالصفحة أشكال مفاهيمية بالذكاء الاصطناعي (PaperBanana) + تحجيم واعٍ بالمؤتمر: تُحفظ الأشكال بحجم الطباعة ولا تُكبَّر أبداً
العزل بيئة مشتركة — المشاريع تتداخل مع بعضها بيئة conda لكل مشروع، HOME معزول، عزل كامل للمستأجرين
النزاهة المحاكاة بدلاً من التجارب الحقيقية مطالبات تمنع المحاكاة + مهارات مدمجة تفرض التنفيذ الحقيقي

عزل البيئة

يعمل كل مشروع في بيئة conda خاصة به، يتم استنساخها من بيئة أساسية عند إنشاء المشروع. وهذا يضمن عزلاً كاملاً:

  • Python معزول — دليل .env/ خاص لكل مشروع مع حزمه الخاصة.
  • HOME معزول — يعمل كل منسق مع ضبط HOME على دليل المشروع.
  • لا تلوث متبادل — تمنع PYTHONNOUSERSITE=1 تسرب حزم المستخدم العامة.
  • تجهيز تلقائي — يكتشف ark run وبوابة الويب بيئة المشروع ويستخدمانها؛ ويقوم المسار بتهيئتها إذا كانت مفقودة.
# يتم إنشاء بيئة conda تلقائياً عند أول تشغيل.
# ark run سيكتشفها ويستخدمها:
ark run myproject
#   Conda env: /path/to/projects/myproject/.env

نظام المهارات

يأتي idea2paper مع مهارات مدمجة — مجموعات تعليمات برمجية يحملها الوكلاء لفرض أفضل الممارسات:

المهارة الغرض
نزاهة البحث تمنع المحاكاة: يجب على الوكلاء تشغيل تجارب حقيقية
التدخل البشري بروتوكول التصعيد: يتوقف الوكلاء للسؤال قبل الإجراءات غير القابلة للتراجع
عزل البيئة يفرض حدود البيئة الخاصة بكل مشروع
صندوق وقت التشغيل يقيّد كل مشروع وقت التشغيل ببيئة conda الخاصة به وHOME ودليل مؤقت خاص
نزاهة الأشكال البيانية يتحقق من مطابقة الأشكال للبيانات؛ يمنع الرسوم الوهمية
تعديل الصفحات يحافظ على حدود عدد الصفحات عبر تعديل كثافة المحتوى

تعيش المهارات المدمجة في skills/builtin/ ويتم تثبيتها تلقائياً أثناء تهيئة المسار. وتقع مهارات المجالات (مثل HPC) في skills/library/، ويختارها الباحث عند الحاجة.

لوحة التحكم (Dashboard)

يتضمن idea2paper لوحة تحكم على الويب لإدارة المشاريع وعرض الدرجات وتوجيه الوكلاء — تعمل من عملية FastAPI واحدة تستضيف الصفحة الرئيسية أيضاً (منفذ واحد، وحدة systemd واحدة). وإلى جانب شارات المراحل والسجلات الحية، تمنحك:

  • اصطفاف عادل — كل إطلاق محدود بتكرارين للتطوير وتكرارين للمراجعة؛ وعندما تمتلئ المسارات، تصطف المشاريع الجديدة في طابور مع رقم ترتيب ووقت إنجاز متوقَّع، ويصلك بريد إلكتروني عند اكتمال الورقة.
  • ميزانيات صادقة — تعرض بطاقة التكلفة الإجمالي كما فوتره المزوّد (فاتورة OpenRouter الفعلية، شاملة البحث العميق والأشكال) متى توفّر، وتُوسم التقديرات بوضوح فيما عدا ذلك.
  • منتقي نماذج واعٍ بالمفاتيح — لا يمكن اختيار سوى النماذج التي تملك مفتاحاً لها؛ ومفتاح OpenRouter واحد يفتح القائمة كاملة.
  • حاور ورقتك — اطرح أسئلة عن مشروع منتهٍ، أو اطلب تعديلات محددة، أو أعد تشغيل تجربة واحدة دون تكرار كامل.
  • أوضاع ملاءمة الصفحات — Relaxed / Balanced / Strict تتحكم في مدى صرامة ملاءمة الورقة لحد صفحات المؤتمر.

الإعدادات

يُضبط الإعداد عبر .ark/webapp.env (يُنشأ تلقائياً عند أول تشغيل لـ ark webapp). اضبط SMTP_* لتفعيل تسجيل الدخول عبر الرابط السحري، واستخدم ALLOWED_EMAILS / EMAIL_DOMAINS لتقييد الوصول، واختيارياً GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET لتفعيل Google OAuth.

ark webapp restart إعادة تشغيل خدمة لوحة التحكم.
ark webapp logs [-f] عرض أو تتبع سجلات الخدمة.
ark webapp login <email> طباعة رابط تسجيل دخول سحري جديد.

استخدام Docker

متطلبات المعمارية

يعتمد وقت تشغيل idea2paper على مكتبات علمية تكون أكثر استقراراً على x86_64. إذا كنت تستخدم Apple Silicon (M1/M2/M3)، يجب عليك البناء لمنصة linux/amd64.

جميع ملفات idea2paper Dockerfiles و docker-compose.yml مضبوطة لفرض linux/amd64 افتراضياً.

التشغيل عبر Docker Compose

أسهل طريقة لتشغيل بوابة idea2paper هي استخدام docker-compose. من جذر المشروع:

# بدء البوابة (يبني الصورة تلقائياً لـ amd64)
docker compose -f docker/docker-compose.yml up --build -d

ستكون البوابة متاحة على http://localhost:9527. يتم حفظ جميع قواعد البيانات والإعدادات والمشاريع تلقائياً في Docker volume باسم ark_data.

لعرض السجلات المباشرة:

docker compose -f docker/docker-compose.yml logs -f webapp

الرفع إلى منصة Google Cloud (GCP)

يتضمن idea2paper سكربت لبناء ورفع الصور إلى Google Artifact Registry أو GCR.

# الرفع إلى Artifact Registry (موصى به)
./docker/push-gcp.sh --project [PROJECT_ID] --region [REGION] --repo [REPO] --build

# الرفع إلى Container Registry القديم (gcr.io)
./docker/push-gcp.sh --project [PROJECT_ID] --legacy --build

يعمل خيار --build تلقائياً على بناء الصور لمعمارية linux/amd64 حتى عند التشغيل على macOS.

الحوسبة السحابية (Cloud Compute)

تفصل بنية السحابة v2 في idea2paper بين مستوى التحكم (Control Plane) ومستوى التنفيذ (Execution Plane)، مما يتيح تشغيل المنسق الكامل على عنقود مُجهَّز عبر SkyPilot بينما تتفاعل أنت مع تطبيق ويب محلي خفيف. أصبح SkyPilot الآن المسار الوحيد للحوسبة السحابية — فهو يُجهِّز الموارد عبر AWS/GCP/Azure/Kubernetes من تجريد واحد، مع مثيلات spot، وإعادة المحاولات، والإنهاء التلقائي (autostop) المدمج.

كيف يعمل: 1. يعمل تطبيق الويب المحلي (أو CLI) كمُطلِق خفيف — فهو يشغّل sky launch لتجهيز عنقود المنسق (Orchestrator) البعيد، ويزامن كود مشروعك (عبر workdir/file_mounts الخاصة بـ SkyPilot) ومفاتيح API، ثم يشغّل عملية المنسق. 2. يشغّل عنقود المنسق كل المنطق عالي المستوى (الباحث، المخطِّط، الكاتب، LaTeX، الأشكال) عن بُعد في جلسة منفصلة. 3. يمكن تشغيل التجارب على عنقود المنسق نفسه أو على عنقود GPU منفصل مُجهَّز عبر SkyPilot (قابل للضبط بشكل مستقل). 4. يبلّغ المنسق عن حالته إلى الديار عبر واجهة /v1 لمستوى التحكم؛ ويبثّ تطبيق الويب السجلات ويحدّث لوحة التحكم. يُنهي العنقود نفسه ذاتياً عبر autostop عند اكتمال التشغيل (أو بعد فترة خمول).

يتم تشفير بيانات اعتماد السحابة في حالة السكون باستخدام SECRET_KEY الخاص بك. لا يتم تسجيل مفاتيحك أو إرسالها إلى أطراف ثالثة.

تسلسل الإعدادات الهرمي (Configuration Hierarchy) يستخدم idea2paper نموذج إعدادات من ثلاث طبقات للحوسبة السحابية: 1. **الإعدادات الافتراضية للنظام**: تُضبط في `webapp.env` (المتغير المركزي `CLOUD_GCP_PROJECT` الذي يحوي صورة ARK المخبوزة، إضافة إلى `CLOUD_LAUNCHER_SA` و`CLOUD_LAUNCHER_SA_KEY` و`CLOUD_CONDA_ENV`). 2. **الإعدادات الافتراضية العامة للمستخدم**: تُضبط في لوحة **Settings** (⚙️). وتنطبق على كل مشاريعك. 3. **تجاوزات المشروع**: تُضبط أثناء إنشاء المشروع أو إعادة تشغيله. ولها الأولوية القصوى. يتيح لك هذا التسلسل تعريف إعدادات افتراضية قياسية مرة واحدة، مع سهولة التبديل إلى مثيل GPU قوي (accelerators، spot) لتجربة محددة.

تفعيل الحوسبة السحابية عبر لوحة التحكم

  1. افتح لوحة Settings (أيقونة ⚙️ في شريط التنقل العلوي).
  2. افتح تبويب Compute.
  3. أدخل GCP Project ID الخاص بك، وامنح حساب الخدمة المعروض ark-launcher الأدوار المطلوبة على مشروعك، ثم انقر Verify access. (لا يتم رفع أي مفتاح لحساب خدمة — بل تفوّض الوصول إلى مشروعك عبر IAM. للمشغّلين: راجع docs/DEPLOYMENT.md §4.)
  4. انقر Save.

عند إنشاء مشروع جديد يمكنك الآن الاختيار بشكل مستقل: - Orchestrator Backend — skypilot لتشغيل مستوى التحكم على عنقود مُجهَّز عبر SkyPilot، أو local لتشغيله على نفس جهاز تطبيق الويب. - Experiment Backend — skypilot لتجارب GPU، أو local لتشغيلها على عنقود المنسق نفسه.

إنشاء مشروع بمجرد ضبط الحوسبة السحابية، أطلق مشروعاً عبر لوحة التحكم: 1. انقر **New Project** من الصفحة الرئيسية للوحة التحكم. 2. املأ هدف البحث، والمؤتمر المستهدف، وأي تعليمات إضافية. 3. انقر **Submit** — يولّد تطبيق الويب ملف `config.yaml`، ويجهّز عنقود المنسق عبر SkyPilot، ويزامن مشروعك، ويبدأ التشغيل. يُخزَّن ملف `config.yaml` المُولَّد في: 
~/.ark/data/projects/<user_id>/<project_id>/config.yaml
يمكنك فحص هذا الملف أو تحريره يدوياً في أي وقت (مثلاً لضبط نوع المثيل أو إضافة `setup_commands`). تسري التغييرات في التشغيل أو إعادة التشغيل التالي. > > إذا كان `PROJECTS_ROOT` مضبوطاً في `.ark/webapp.env`، فسيُستبدل المسار أعلاه بـ `$PROJECTS_ROOT///config.yaml`.

إعداد مزودي السحاب

إعداد مشغّل GCP / AWS / SkyPilot — بناء الصورة المخبوزة، وإنشاء هوية ark-launcher المركزية، وضبط webapp.env — هو مهمة مشغّل تُنفَّذ مرة واحدة لكل نسخة مستضافة. وهي موثّقة خطوة بخطوة لكل سحابة في دليل النشر (بالإنجليزية):

→ docs/DEPLOYMENT.md — §4 GCP · §5 AWS · §6 إعداد العملاء · §8.4 مرجع config.yaml.

إن كنت تستخدم نسخة مستضافة، فلا حاجة لتشغيل أيٍّ من ذلك — افتح فقط Settings → Compute، أدخل مشروع GCP / حساب AWS الخاص بك، وانقر Verify access (أعلاه). التشغيل على Azure أو Kubernetes؟ يدعم SkyPilot ذلك أيضاً؛ اضبط بيانات اعتماد تلك السحابة وفق توثيق SkyPilot.

بثّ السجلات وإعادة الارتباط - **بثّ السجلات** — يبثّ عنقود المنسق السجلات إلى الديار عبر واجهة `/v1` لمستوى التحكم؛ ويستقصيها تطبيق الويب دورياً لعرض التقدم الحي. - **مزامنة الحالة** — يحفظ المنسق نقاط تفتيش لحالة `auto_research/` إلى مستوى التحكم دورياً، فتبقى واجهة لوحة التحكم محدَّثة ويبقى التشغيل صامداً عند فقدان الـ VM. - **إعادة الارتباط** — إذا أعدت تشغيل تطبيق الويب المحلي، يكتشف idea2paper عنقود SkyPilot المُخزَّن ويعيد الارتباط بالعملية الجارية دون إعادة تجهيز.
التحكم في التكاليف > > تُحاسَب العناقيد السحابية بالساعة. يعتمد idea2paper على الإنهاء المدمج في SkyPilot لمنع التكاليف الجامحة: > > - **Autostop-down** — يُطلَق كل عنقود بنافذة autostop-down؛ فإذا بقي خاملاً بعد تلك النافذة **أنهى نفسه**. عناقيد التجارب *تُنهى دائماً* تلقائياً (يمكن ضبطها فقط، لا تعطيلها)؛ أما عناقيد المنسق فتفترض نافذة كشبكة أمان عند الأعطال (قابلة للضبط عبر `idle_minutes_to_autostop`). > - **الإيقاف اليدوي** — النقر على **Stop** في لوحة التحكم يُفرِّغ النتائج ويُنهي العنقود (`sky down`). > > إذا قُتلت عملية تطبيق الويب فجأة، فإن نافذة autostop-down تُنهي العنقود بنفسها. تحقق دائماً من عدم بقاء عناقيد شاردة (`sky status`) بعد الإغلاق غير المتوقع.

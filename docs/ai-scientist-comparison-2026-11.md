# AI Scientist 系统与 Idea2Paper 的实测对照

2026 年 11 月 18 日。研究范围是可以用代码和数据检验的计算研究。一个研究者在这里要做三种代价很不一样的决定：用现有结果写作、用现有原始数据纠正解释、花计算预算取得缺失的观测。本次以这三种决定为比较单位，并单独测试评审者判断错误时系统能否发现。

## DSH 托管流程的变化

1. **规划和审批。** 规划器先检查已有结果，再记录可信的替代解释、能区分两个解释的最小对照、两种可能的结果和停止条件。涉及比较时可声明必须匹配的属性，例如测试输入的摘要。审批和执行看到同一对字段。纯描述性研究可以省略这些字段。
2. **执行和恢复。** 已批准的字段指针随现有实验 checkpoint 持久化，先于作业提交。续跑沿用这份记录。评估器从两个不同的原始结果位置读取字段。字段缺失或不一致时，只能分别报告两组观测。后续计划可以用 `replaces` 指明要补做的旧对照，新的结果另存。新对照匹配后可以支持新结论，旧对照的限制仍交给写作者。只复用旧标签无法解除限制。交给写作者前再检查一次，覆盖中断期间原始文件变动的情况。
3. **分析和判断。** 对评审列出的可重算比较，程序从原始 JSON 指针计算差、比值或相对变化百分比。分母、方向、有效精度和显式舍入都影响结果。明确反例可以直接触发重分析。多步推导可以交代计算和限制，无须硬凑两个不等价的原始字段。该机制不能自动发现所有自然语言主张，也不能证明一个分组字段真实反映了实验代码的行为。

这些变化走网站使用的 DSH 工作流和现有 Python 阶段，无需分叉 DSH 的模型与工具内环。单纯让更多 agent 多评几轮，会增加费用，同时允许它们共同接受同一个错误前提。

## 同模型比较

三组均使用 Google 原生 Gemini 4 Hydrogen、DSH 0.2.1rc2 和相同的原始文件、角色工具及单次输出上限。通用组直接告诉 agent 可以选择三种行动，构成有能力的对照；它使用相同的 Idea2Paper DSH 适配器。线上组和候选组调用各自真正的 `_evaluate_completeness`，用同一适配封装提供研究输入和收集返回值。这里测的是阶段决策，没有启动整篇论文，也没有让 Codex 扮演实验模型。

| 单次输出上限和样本 | 通用 DSH 提示 | 线上 v0.5.48 | 最终候选 |
| --- | ---: | ---: | ---: |
| 1,800 token，6 题 | 5/6 | 4/6 | 6/6 |
| 6,144 token，前 6 题与后加 3 题 | 9/9 | 6/9 | 9/9 |

第一版候选在低上限只有 4/6，在较高上限为 5/6（前六题）。遇到需要多步算术的错误声明时，它会耗尽输出仍不给决定。缩短评审任务，允许直接提交文字反例后，重跑了全部候选题。前三组开发结果仍保留。为减少针对这六题修改造成的偏差，提示定稿后又加入三道不同任务，三组都做了一遍，期间没有再调提示。较高上限时，线上组会把一项能就地纠正的错误带进写作，另外两项送去采集新数据；其中有回复在理由里已经识别出了问题。评分按软件下一步实际会做什么。设计没有多随机种子或独立课题抽样，不能由此估计一般胜率。通用 DSH 在较高上限同样答对全部题目。

本次实际调用了一次 Google 原生 Deep Research，用它找系统、术语和反例。表格中的数字另行核对了作者论文或固定版本的代码。决策对照共运行 57 个样本，包含第一版失败和最终复测。逐题记录给出未完成的调用、实际动作和工具次数。[机器可读结果](ai-scientist-decision-results.json)

为每个 case 和 arm 分别启动 Python 进程，在 `PYTHONPATH` 指向相应 checkout 时调用脚本。环境中提供获授权的 Google 凭据，`--out` 放在临时项目以外。例如，下面这条命令在候选 worktree 根目录运行，需要使用装有固定 DSH SDK 的 Python。[决策对照脚本](../scripts/eval_research_decisions.py)

## 一个有明确真值的 Slurm 反例

作业 **88939** 在 mcnode15 的 Slurm 集群运行完成，退出码 0。我们分别测量顺序求和与分块求和，两个实现都对 32 组向量运行，用精确有理数求和作为参照。实验代码根据它实际读取的浮点值计算输入摘要。随后在独立 Python 进程重跑，两份 JSON 与 Slurm 输出完全一致。[可复现实验](../test_fixtures/scientific_comparison/summation.py)

| 条件 | 顺序求和平均绝对误差 | 分块求和平均绝对误差 | 评审一律给出“充分”时，候选系统的实际决定 |
| --- | ---: | ---: | --- |
| 两臂输入不同 | 15.96875 | 0 | 匹配条件失败。先获取同输入对照；若预算已到，只能分别报告两组观测。 |
| 两臂使用相同输入 | 15.96875 | 15.96875 | 接受此次受控比较。该工作负载未测出误差改善。 |

再把两个条件分别交给真实 DSH 写作者，从实际写作提示生成结果段。输入不同时，它报告了两个数值并指出无法归因于分块求和。输入一致时，它报告了持平。这里故意固定了评审结论，以单独检验软件兜底。另起一次真实 DSH 规划会话，只给它早期的结果文件和研究问题。规划器自己写出一项同输入对照，指定两臂各自的原始摘要字段，生成的计划通过了 checkpoint 格式校验。

最后用同一份程序、两次观测和一份已核实的参考文献实际生成了完整 LaTeX 短文。在干净目录用独立 TeX 和 BibTeX 进程重编，再带上原始结果及 findings 运行项目交付检查。PDF 共 4 页，正文 3 页，硬性检查 0 项违规，软性检查中页数超过要求 1 页。摘要、结果表和结论均区分了早期观察与同输入结果。原写作会话消耗完输出预算；一次限时续接也未完成。在这个尺度上验证了主结论的归因，整次自动交付仍有篇幅和成本问题。[用于背景核验的 Higham 原文](https://epubs.siam.org/doi/10.1137/0914050)

## 对产品的判断

已经测到的收益是阻止错误归因、避免把可用旧数据纠正的问题送回集群，并在交给写作者时保留限制。对于会主动读数据的强通用 agent，这批简单题目的自然语言判断已接近上限。下一项能真正区分产品的评测，应把未见的真实项目冻结在出结果前，让两组在相同预算下从计划一路交付，以独立重跑能支持的主结论、无效集群支出、研究者救场次数和盲评为准。要主张错误率下降十倍，需要足够多的基线失败和新项目上的重复观测。
